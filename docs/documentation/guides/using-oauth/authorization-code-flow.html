Authorization Code Flow

Original: https://community.developer.battle.net/documentation/guides/using-oauth/authorization-code-flow

The OAuth 2.0 Authorization Code Flow allows an application to access a user's data on their behalf. This allows an application to acquire more sensitive, opt-in information about a user, such as their list of World of Warcraft characters, after obtaining the user's permission to do so. The Authorization Code Flow has two major parts: the authorization code request and the access token request.

For more detailed information about the Authorization Code Flow, see the OAuth 2.0 Authorization Framework RFC.

Currently, the authorization code flow provides access tokens for the following requests:

  • GET /userinfo*
  • GET /profile/user/wow
  • GET /profile/user/wow/protected-character/{realm-id}-{character-id}
  • GET /profile/user/wow/collections
  • GET /profile/user/wow/collections/pets
  • GET /profile/user/wow/collections/mounts

* Note: GET /userinfo uses oauth.battle.net as the host for requests.

Obtaining Authorization from the User

For an authorization code request, an application needs to either redirect the browser or open a new window to the authorize URI with the following query parameters:

Parameter

Description

client_id

The developer's client ID.

scope

The space-separated scope values to request from the player.

state

A semi-random data blob to send back with when completing authorization.

redirect_uri

The redirect location. Should either be https://localhost for testing or the redirect_uri configured in the API Access tool.

response_type

The code type being requested. For the authorization code flow, this value should be code.

After the player has granted authorization, the auth provider redirects the browser to the specified redirect_uri and includes the provided state and a single-use code as query parameters. The authorization code represents the user's agreement to allow an application to access their data. It will next be exchanged by the application for an access_token for making API requests on behalf of the user. As to the returned scope list, note that users can fine-tune which ones they authorize: therefore, the returned list may contain fewer scopes than originally requested.

Example flow

Application redirects browser to obtain user authorization 
https://oauth.battle.net/authorize
            ?response_type=code
            &scope=openid
            &state=AbCdEfG
            &redirect_uri=https://localhost
            &client_id=<CLIENT ID>
User authenticates & authorizes individual scopes handled by auth provider...
Auth provider redirects browser back to application 
https://localhost
            ?code=<AUTHORIZATION CODE>
            &state=AbCdEfG
Application continues see next section...

Exchanging an Authorization Code for an Access Token

To request an access token, the application needs to provide the following POST parameters to the token URI, using the developer's client ID and secret with HTTP basic authorization:

Term Description

redirect_uri

The same redirect_uri used when obtaining the authorization in the previous step.

grant_type

The grant type being requested. For the authorization code flow, this value should be authorization_code.

code

The code value provided in the redirect when obtaining authorization in the previous step.

The auth provider will respond with a JSON structure containing an access token. From there, applications can use the access token to access any of the allowed resources on behalf of that player.

Example CURL command

This CURL command converts an authorization code into an access token for calling APIs on behalf of the client application and authenticated user.

curl -X POST https://oauth.battle.net/token
-u <developer client id>:<developer secret>
-d redirect_uri=<redirect URI used in authorize request>
-d grant_type=authorization_code
-d code=<authorization code>

Expected response

{
    "access_token": "USVb1nGO9kwQlhNRRnI4iWVy2UV5j7M6h7",
    "token_type": "bearer",
    "expires_in": 86399,
    "scope": "openid"
}

API request format

After an application retrieves an access token, it provides that token when making requests to API resources. This is done via an authorization header as follows:

{
    curl --header "Authorization: Bearer " REST API URL
}

Notes:

  • While providing the token via a form-encoded body parameter is allowed by RFC-6750, all of our current community APIs are GET-based, so this method does not apply.
  • Providing the token in the URL via a query string parameter will no longer be supported from September 30, 2024.

Getting a User's Account ID and BattleTag

The GET /userinfo endpoint returns a user's Account ID and BattleTag so that a third-party site knows a player's identity when they log into the site with a Battle.net Account.

Making the request

GET /userinfo requests work like other Battle.net API OAuth requests:

  1. Retrieve an access token via the OAuth authorization code flow.
  2. Make a GET request to https://oauth.battle.net/userinfo, providing the access token in an Authorization header: 
    curl -X GET
    'https://oauth.battle.net/userinfo'
    -H 'Authorization: Bearer <access token>

The response returns the user's Account ID and BattleTag.
