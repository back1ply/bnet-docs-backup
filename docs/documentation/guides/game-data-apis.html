Game Data APIs

Original: https://community.developer.battle.net/documentation/guides/game-data-apis

Game data and profile APIs allow Battle.net to share game information via a single, well-defined interface in an easily-consumable format that has an agreed-upon schema between publisher and consumer. Developers can use game data and profile APIs to retrieve the following types of information:

  • World of Warcraft realm, Mythic dungeon, achievement lists, and WoW Token data.
  • Diablo III seasonal, era, and leaderboard information.
  • Hearthstone cards, decks, and metadata

Game data APIs versus profile APIs

The difference between game data and profile APIs is the type of game data they handle:

  • Game data API: Stores all other reference data related to a game itself (collectively called static data) and changing, world-related data that is not connected to players (called dynamic data)
  • Profile API: Stores data related to individuals, their characters, or accounts (collectively called profile data).

Game data includes generic information like a list of abilities available to a character, server status, or leaderboards. Profile data includes the equipment on a character, an account's achievements, or a list of characters.

Game data and profile API details

The section below details specific information about game data and profile API structure, namespaces, authorization, and response format.

Structure

Game data and profile APIs return JSON documents directly to the consumer in the exact format and structure they are stored. The only time a document is returned in a format different than the one in which it was originally stored is when the consumer makes a request that includes a localization identifier.

Namespaces

Game data and profile APIs include namespaces. Namespaces allow the publishing of multiple documents to a single URL without overwriting an existing document. This allows all versions of that document to remain accessible within a specific context.

Although this allows multiple instances of the same type of document to coexist, namespaces should not be considered strict or semantic versioning, even if the namespace contains a version identifier.

Specifying namespaces

There are currently two methods for specifying a namespace when making a request to the Game Data and Profile APIs:

Type

Name

Query Parameter

?namespace=

Request Header

Battlenet-Namespace

What data is namespaced?

All data published to the game data and profile APIs are published to namespaces. However, the naming strategies and when those names change are determined by an API's publisher.

Authorization

In game data and profile APIs, consumers must provide an access_token query parameter or an Authorization: Bearer <token> header when making a resource request.

To obtain an access_token, follow the OAuth client credentials flow.

Response format

Responses from game data and profile APIs represent a single resource in full, rather than a composite object that represents several other objects. This means that for some data, the consumer may need to make several requests to related resources by following links in the originally requested resources before they can obtain all the desired data.

JSON Document Links

The Game Data and Profile APIs attempt to increase discoverability by providing an object called a link in addition to any numerical IDs or strings.

These links are structured as an object that is referenced by a property named key that contains an HREF field that is a URL to a related resource. However, links can also contain other commonly-referenced data, like localized strings.

    "href": "https://us.api.blizzard.com/data/wow/journal-instance/758?namespace=static-us"

Throttling

API clients are limited to 36,000 requests per hour at a rate of 100 requests per second. Exceeding the hourly quota results in slower service until traffic decreases. Exceeding the per-second limit results in a 429 error for the remainder of the second until the quota refreshes.
