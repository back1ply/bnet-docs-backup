Regionality and APIs

Original: https://community.developer.battle.net/documentation/guides/regionality-and-apis

Battle.net employs several region-based concepts to manage and deliver game data. The following documentation outlines how data is separated for API consumers.

Account partitions

Battle.net operates two main account partitions: one in China and one for the rest of the world. When any data or concept is described as "unique" in documentation, that data or item resides within a particular partition. API requests cannot retrieve global information from the China partition, and vice versa.

Account ID

Battle.net uses Account IDs, which are 64-bit unsigned integers, to uniquely identify users within a particular account partition.

Developers should use an accountId to link a user into their applications wherever possible.

Regions

API data is limited to specific regions. For example, US APIs accessed through us.battle.net only contain data from US battlegroups and realms. Locale support is limited to locations supported on Blizzard community game sites.

Game information is different from region to region. For example, a user that has both US and EU WoW accounts has different characters, achievements, and other information in each region. Likewise, a D3 user who has a single license for D3 on their account has a different character list for each region in which the game operates.

For optimal user experience, applications should use the region closest to the user for retrieving account data. Applications may need to request game data for multiple regions if the user indicates that they play in multiple regions.

Getting a profile's region and realm IDs

To get a profile's region and realm ID, make a request to GET /player/{accountId}. The response includes the user's name, profile URL, avatar URL, profile ID, region ID, and realm ID.

Localization

All available API resources provide localized strings using the locale query string parameter. Supported locales vary from region to region and align with those supported on Blizzard community sites.

To access a different region in an API request, add the locale query parameter. For example, the request to retrieve the European Diablo III item type list localized in French uses this format:

http://eu.api.blizzard.com/d3/data/item-type?locale=fr_FR

Locale in default Game Data API responses

The default for Game Data API response objects includes all locales for a localized string that filters down to a specific locale, if one is specified in the request. To specify localization in an API request, use the locale query parameter in the request URL. API requests use the locale query parameter to provide return text in a preferred language (defaulting to en_US).

Note: the default language for Community API responses is en_US unless a request includes a specific locale query parameter.
